# 북적북적 — 책 너머, 우리의 이야기

독서모임 **북적북적**이 2025년 7월부터 함께 읽은 책과 예정된 다음 모임을 기록하는 반응형 웹진형 정적 웹사이트입니다. 모임 기록을 한곳에 모으고, 향후 발제문·후기·사진이 있는 웹진으로 확장하기 쉬운 구조를 목표로 합니다.

## 현재 구현된 기능

- 2025.07.16.~2026.08.26. 기록된 **14권**의 아카이브, 2026.09.30. **예정된 15번째 모임** 별도 소개
- 모든 책의 표지 이미지, 제목, 저자, 날짜, 진행자 영문 이니셜 표시; 책 상세 모달에서 원본 도서 정보 페이지 연결
- 아카이브의 연도별 필터(전체 / 2026 / 2025), 책·저자·진행자 이니셜 검색, 최신순/오래된순 정렬, 빈 결과 안내
- 기존 책 세 권에서 출발한 편집자의 질문을 담은 **웹진 섹션**. 실제 모임의 발제문이나 후기로 표기하지 않음
- 모바일/태블릿/데스크톱 반응형 레이아웃, 키보드 접근 가능한 버튼·대화상자, 이미지 대체 텍스트, 읽기 쉬운 보조 글씨와 조작 영역
- 서울 날짜 기준으로 예정 모임의 노출 상태를 갱신. 예정일이 지나면 진행 여부를 단정하지 않고 **기록 확인 중**으로 안내
- 로컬 이미지 파일 사용으로 외부 이미지 서버에 대한 실시간 의존 없음 (Google Fonts는 외부 제공)

## 진입 경로 / URI

- `index.html` 또는 사이트 루트 `/` — 전체 웹진
- `/#about` — 모임 소개 / 히어로
- `/#upcoming` — 예정된 다음 모임
- `/#journal` — 웹진의 편집자 질문
- `/#archive` — 읽은 책 아카이브
- 검색·필터·정렬·상세 모달은 페이지 내 동작하며 별도 URL 파라미터는 사용하지 않습니다.
- 외부 도서 정보 링크는 각 모달의 **책 정보 보러 가기** 버튼을 통해 열립니다. 자체 API 엔드포인트는 없습니다.
- 공개 웹페이지: https://uincity.github.io/bookjeok/
- GitHub 저장소: https://github.com/uincity/bookjeok

## 데이터 모델 및 파일 구조

- `js/main.js`의 `books` 배열에 각 모임 기록을 저장합니다. 필드: `no`(순번), `date`(날짜), `title`(책 제목), `author`(저자), `host`(발제자/진행자의 영문 이니셜), `cover`(로컬 표지 경로), `source`(표지/도서 정보 출처), 선택 필드 `upcoming`, `note`. 책 수·기록된 모임 수·연도 필터·이슈 번호는 이 배열에서 계산합니다.
- `images/book-01.jpg` ~ `images/book-15.jpg` — 도서 표지 이미지. 표지는 검색 결과에서 알라딘, 예스24, 민음사/황금가지, 창비 등의 해당 책 페이지를 확인한 뒤 로컬 사본으로 저장했습니다. 원본 도서 정보 출처는 데이터의 `source` 필드에서 확인할 수 있습니다. 표지 이미지의 저작권은 각 권리자에게 있습니다.
- `css/style.css` — 편집 디자인과 반응형 스타일.
- 저장 서비스 및 DB: 사용하지 않음. 현재 모임 기록은 정적 JavaScript 데이터로 관리합니다.

### 판본 관련 메모

10번째 모임의 책 제목은 제공받은 기록대로 **「인간은 무엇으로 사는가」**로 표기했습니다. 찾아서 적용한 표지 이미지는 톨스토이의 **「사람은 무엇으로 사는가」** 판본으로, 상세 모달에도 차이를 명시했습니다. 정확한 읽은 판본의 표지가 확인되면 이미지와 출처를 교체하는 것이 좋습니다. 다른 책들도 실제 모임에서 읽은 판본과 표지 버전이 다를 수 있습니다.

## 아직 구현되지 않은 기능

- 개별 모임의 발제문, 대화 기록, 리뷰, 사진 및 독립 기사 페이지
- 관리자용 게시 기능 또는 서버 기반 콘텐츠 편집/저장
- 예정일이 지난 모임의 실제 진행 여부를 확인하거나 아카이브에 자동으로 올리는 기능. 확인되지 않은 모임은 `upcoming` 상태로 두고 기록 확인 안내를 표시합니다.
- 모임 신청, 댓글, 회원 기능

## 다음 개발 권장 사항

1. 실제 모임에서 사용한 판본 표지와 모임 날짜·진행자 정보를 확인합니다.
2. 새 모임을 기록할 때 `js/main.js`의 `books`에 항목을 추가하고 `images/`에 표지 파일을 넣습니다. 실제 진행이 확인된 모임만 `upcoming`을 제거합니다. 다음 모임 배너는 예정된 책 데이터에서 자동으로 채웁니다.
3. 발제문·후기 콘텐츠가 모이면 각 모임에 `slug`, `summary`, `article` 등을 추가해 개별 기사 페이지 또는 웹진 이슈 페이지로 확장합니다. 현재 웹진 섹션의 질문은 편집 콘텐츠이며 실제 모임 기록과 구분합니다.
4. 편집자가 브라우저에서 콘텐츠를 추가해야 한다면 RESTful Table API용 테이블 스키마를 만들고 데이터 관리 UI를 별도로 설계합니다.
